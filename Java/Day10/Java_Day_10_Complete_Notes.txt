Day 10 focused on Abstraction and combined the major OOP concepts learned during Days 6–10 into one QA automation-style exercise.

1. ABSTRACTION
--------------
Abstraction means hiding implementation details and showing only necessary functionality.

Abstract class:
abstract class Test

Abstract method:
abstract void executeTest();

An abstract method has no implementation in the parent. Child classes provide the implementation.

An abstract class can also contain normal methods.

2. NORMAL METHODS IN ABSTRACT CLASS
-----------------------------------
An abstract class can contain normal methods shared by child classes.

Example:
void startTest()
{
    System.out.println("Starting test");
}

3. MULTIPLE CHILD CLASSES
-------------------------
One abstract parent can have multiple child classes.

Example structure:

abstract class Test
       |
       +---- GameTest
       |
       +---- WebTest

Each child overrides executeTest() with its own implementation.

4. ABSTRACT CLASS CONSTRUCTOR
-----------------------------
An abstract class can have a constructor.

Example:
abstract class Test
{
    String clientName;

    Test(String clientName)
    {
        this.clientName = clientName;
    }
}

The abstract class cannot be instantiated directly, but its constructor runs when a child object is created.

Execution order:
GameTest constructor
    ↓
super(...)
    ↓
Test constructor
    ↓
Parent fields initialized
    ↓
Back to GameTest constructor
    ↓
Child fields initialized

5. super()
----------
super() calls the parent constructor.

Example:
GameTest(String testName, String clientName,
         String gameName, boolean result)
{
    super(testName, clientName);
    this.gameName = gameName;
    this.result = result;
}

6. RUNTIME POLYMORPHISM
-----------------------
A parent reference can point to a child object.

Example:
Test test1 = new GameTest(...);
Test test2 = new WebTest(...);

test1.executeTest();
test2.executeTest();

Java executes the overridden method belonging to the actual child object.

The parent Test class contained:
- private testName

8. ENCAPSULATION
----------------
Private fields protect object data.

Example:
private String testName;

Getter:
public String getTestName()
{
    return testName;
}

Setter:
public void setTestName(String testName)
{
    this.testName = testName;
}

9. this KEYWORD
---------------
this refers to the current object.

Example:
Test(String testName, String clientName)
{
    this.testName = testName;
    this.clientName = clientName;
}

10. STATIC
----------
projectName was made static because it is shared by all tests in the same project.

Example:
static String projectName;

Set the shared value:
Test.projectName = projectName;

Static data belongs to the class rather than each object.

Comparison:
testName     -> unique to each test object
clientName   -> stored in each test object
projectName  -> shared by all Test objects

11. METHOD OVERLOADING
----------------------
Three runTest() methods were created:

void runTest()

void runTest(String buildVersion)

void runTest(String buildVersion, int testCase)

Same method name, different parameter lists.

Examples:
test1.runTest();
test1.runTest(buildVersion);
test1.runTest(buildVersion, testCase);

12. METHOD OVERRIDING
---------------------
The parent declared:
abstract void executeTest();

GameTest implemented its own version:
@Override
void executeTest()
{
    ...
}

WebTest implemented its own version:
@Override
void executeTest()
{
    ...
}

13. SCANNER INPUT
-----------------
The final program accepted:

- Number of Test Cases
- Game Name

- Web Page
- URL
- Web Result

Important Scanner rule:

After nextInt() or nextBoolean(), consume the leftover newline before using nextLine().

Example:
int testCase = scan.nextInt();
scan.nextLine();

String gameName = scan.nextLine();

Similarly:
boolean result = scan.nextBoolean();
scan.nextLine();
